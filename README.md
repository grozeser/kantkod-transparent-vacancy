# Прозрачная вакансия

«Прозрачная вакансия» проверяет объявления о работе в Калининградской области. Редактор видит, какие условия отсутствуют, допускают несколько прочтений или противоречат друг другу. К каждому замечанию сервис прикладывает исходное поле, цитату и вопрос работодателю.

**Для жюри** · [Быстрый запуск](#быстрый-запуск) · [Сценарий проверки](#сценарий-для-жюри) · [Формат отчёта](#формат-json) · [Вклад команды](#вклад-команды)

Готовые материалы для проверки в репозитории: [учебный набор](examples/sample-vacancies.json), [пример JSON-отчёта](examples/sample-report.json) и [результаты проверки ИИ](examples/model-evaluation.json).

## Быстрый запуск

Требуется **Python 3.12**. Основная зависимость — **scikit-learn 1.9.0**. Её версия закреплена в [requirements.txt](requirements.txt). Установка пакетов может потребовать интернет. После установки локальный анализ с ИИ работает без аккаунта, платной подписки и ключа API.

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
$py = (Resolve-Path .\.venv\Scripts\python.exe).Path
& $py -m pip install -r requirements.txt
& $py -m kantkod check --input examples/sample-vacancies.json
```

Ожидаемый результат — `var/check-report.json` с **10 уникальными вакансиями**. Чтобы открыть кабинет, запустите:

```powershell
& $py -m kantkod serve
```

В браузере откройте [127.0.0.1:8765](http://127.0.0.1:8765/). Для Linux и macOS команды быстрого запуска выглядят так:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m kantkod check --input examples/sample-vacancies.json
.venv/bin/python -m kantkod serve
```

## Сценарий для жюри

1. Найдите `DEMO-39-004`. В обязанностях обещана полная удалёнка, в требованиях указан обязательный ежедневный офис. Откройте замечание, чтобы увидеть обе цитаты и вопрос работодателю.
2. Нажмите **«Проверить перед публикацией»**. Для учебного сценария выберите **«Гибрид»** и **«Ср»** как офисный день. Оставьте выбранной одну цитату и проверьте черновик. Анализатор покажет, что противоречие осталось.
3. Выберите обе цитаты и запустите проверку снова. Кабинет покажет изменения по каждому полю, закрытые и оставшиеся замечания. Текст можно скопировать. Исходная вакансия, конкурсный JSON и рабочие статусы сохраняются.

Для ежедневной работы в кабинете есть поиск по должности, работодателю и ID, фильтры по теме и виду замечания, карта семи условий, выгрузка карточки и пакет вопросов работодателю. Уточнения можно перевести в статус «К отправке», «Ждём ответа» или «Уточнено». Если при очередной загрузке подтверждённое условие изменится, сервис вернёт в работу только связанное уточнение.

## Источники и расписание

### Проверка собственного файла

```powershell
& $py -m kantkod check --input "C:\data\vacancies.json" --output var/jury-report.json
& $py -m kantkod serve --report var/jury-report.json
```

Вход повторяет формат ответа API. В `results.vacancies` передаётся массив. В каждой его записи есть объект `vacancy` с непустым полем `id`. Для независимого запуска можно указать `--db var/jury.sqlite3` в обеих командах.

### Загрузка из API региона 39

```powershell
& $py -m kantkod live --limit 10 --page-size 5
& $py -m kantkod serve --report var/live-report.json
```

Конфигурация хранится в [config.json](config.json). Параметры `--limit`, `--page-size` и `--offset-unit` позволяют изменить соответствующие настройки для одного рабочего запуска.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `source_url` | API «Работа в России», регион 39 | Адрес источника |
| `max_vacancies` | `100` | Максимум уникальных вакансий |
| `page_size` | `50` | Максимальный размер запроса к одной странице |
| `offset_unit` | `page` | `page` — смещение в страницах, `item` — в записях |
| `timeout_seconds` | `20` | Таймаут одного запроса |
| `schedule_time` | `09:00` | Ежедневное время запуска по местным часам Windows |

Сервис забирает несколько страниц, когда это позволяют лимит и объём данных, и объединяет повторяющиеся ID. Повторный анализ переиспользует неизменившиеся записи при той же версии правил и модели. При ошибке загрузки сохраняется последний успешный отчёт, а кабинет показывает сообщение о сбое.

### Windows Task Scheduler

```powershell
.\automation\install-task.ps1 -Python $py -Preview
```

`-Preview` показывает команду, рабочую папку и время. Если параметры подходят, запустите скрипт без `-Preview` для регистрации задачи. Планировщик вызывает `python -m kantkod live --config ...`. Он обрабатывает данные тем же способом, что ручной рабочий режим. Модель и проверочный режим ключей не требуют. Если расширяете проект собственными интеграциями, храните их ключи вне Git.

## Где применяется ИИ

Точка входа для обоих режимов — [kantkod/__main__.py](kantkod/__main__.py). Команды `check` и `live` передают записи в общий [пайплайн](kantkod/pipeline.py). [Правила](kantkod/analysis.py) сопоставляют структурированные поля и текст. Они находят явные пропуски и противоречия. Семь тем — должность, обязанности, требования, оплата, график, место работы и тип занятости.

Для оставшихся неоднозначных формулировок пайплайн использует [локальную модель](kantkod/model.py). **TF-IDF и логистическая регрессия** на scikit-learn оценивают фрагменты, где структурированных сведений недостаточно. Если модель добавила замечание, его можно найти по `method: "ml"`. Вопросы формируются из тематических шаблонов, а цитаты берутся из входных данных. Предпросмотр черновика использует тот же анализатор.

## Формат JSON

`meta` содержит источник, время, версии модели и правил, числа страниц, вакансий и повторно использованных результатов, а также диагностические сообщения. `vacancies[]` содержит `id`, `url`, `title`, сведения о работодателе и массив `issues`. Значение `url: null` означает, что во входе не было пригодной ссылки. Пустой `issues` означает, что сервис не нашёл замечаний в проверенных условиях.

Пример одного замечания из [учебного отчёта](examples/sample-report.json):

```json
{
  "topic": "workplace",
  "type": "conflict",
  "method": "rules",
  "evidence": [
    {
      "field": "duty",
      "quote": "Работа полностью дистанционная из любого города."
    },
    {
      "field": "requirement.qualification",
      "quote": "Обязательное ежедневное присутствие в офисе в Калининграде к 09:00."
    }
  ],
  "problem": "Полная удалёнка несовместима с обязательным присутствием в офисе.",
  "recommendation": "Какой формат действует: офис, гибрид или удалёнка? Если нужен офис, укажите адрес и дни присутствия."
}
```

`type` принимает значения `missing`, `ambiguous` и `conflict`. `method` показывает вклад правил (`rules`) или модели (`ml`). Для пропуска `evidence.field` указывает на поле с недостающими сведениями, а цитата пуста. Для противоречия приведены оба основания. SQLite хранит рабочие статусы и кэш. Отчёт содержит результаты анализа исходных вакансий, а черновик проверяется отдельно по запросу редактора.

## Проверки и результаты

```powershell
& $py -m unittest discover -s tests -v
& $py -m kantkod evaluate --set holdout
```

- **22 автотеста** покрывают входной формат, пагинацию, дубли ID, сохранение отчёта при сбое, контекст замечаний, кэш, переоткрытие уточнений и проверку черновика.
- **Рабочий прогон** получил 2 страницы и 10 уникальных вакансий из API региона 39. Одноразовая задача Windows Scheduler проверена на локальном имитаторе API.
- **Вклад ИИ** проверен на 20 синтетических сценариях. Правила нашли 7 верных замечаний, модель добавила ещё 5. Итог — 12 верных, 0 ложных и 0 пропущенных замечаний на этой подборке. [Протокол сравнения](examples/model-evaluation.json) относится к контрольной синтетике.
